# 실시간 얼굴 비식별화를 위한 카툰화 모듈 — 케이스 스터디

> **담당 범위 표기 미정.** 공개 전에 이 블록을 채우거나 지울 것.
> (설계·판단·검증 / 구현 / 협업 도구 사용 범위를 어떻게 쓸지 결정 필요)

---

## 요약

영상 속 얼굴을 **모자이크 대신 애니 스타일로 다시 그려** 비식별화하는 실시간 모듈을 만들었다.
20B 확산 모델을 teacher로 두고 **4.06M 파라미터 CNN에 증류**해, 단일 GPU에서 실시간으로 돌린다.

| 항목 | 시작 | 현재 | 비고 |
|---|---|---|---|
| 화풍 재현 (val L1) | 0.1611 | **0.1448** | 낮을수록 teacher에 가까움 |
| 시간적 안정성 (비등변성) | 1.104 | **0.569** | 0에 가까울수록 프레임 간 일관 |
| 영상 흔들림 (모션 보정 잔차) | 5.757 | **3.848** | −33% |
| 영상 선명도 (엣지 대비) | 174.8 | **181.0** | +3.5% |
| **블라인드 사람 평가** | — | **85.2% 승 (p<0.0001)** | 고정 홀드아웃 60쌍, 기준선 대비 |
| 처리 속도 | 5.55× 실시간 | **1.02× 실시간** | 요구사항 ≤2× |
| **비식별화 (신원 cos)** | — | **0.595** | **목표 0.3, 미달** |

**정직하게 적자면 이 프로젝트는 아직 목표를 달성하지 못했다.** 화질·속도·안정성은 요구선을 넘겼지만
제품의 존재 이유인 비식별화 지표가 목표의 두 배다. 이 문서는 그 사실을 포함해
**무엇을 시도했고, 무엇이 틀렸고, 그것을 어떻게 알아냈는지**를 기록한 것이다.

## 1. 문제 정의

### 왜 모자이크가 아닌가

기존 얼굴 비식별화 파이프라인은 검출된 얼굴을 픽셀화하거나 블러 처리한다. 안전하지만
**영상의 정보가 통째로 사라진다.** 표정도, 시선도, 사람이 몇 명인지 외에는 아무것도 남지 않는다.

목표는 "얼굴을 가리는 것"이 아니라 **"누구인지 모르게 하되 사람으로 보이게 하는 것"** 으로 잡았다.

### 하드 제약

| 제약 | 내용 | 왜 어려운가 |
|---|---|---|
| 라이선스 | 코드·가중치·데이터 전부 Apache 2.0 / MIT | 쓸 만한 애니 스타일 모델은 **대부분 비상업 라이선스** |
| 속도 | 1분 영상 → 2분 이내 (단일 GPU) | 20B 확산 모델은 장당 12.6초. **런타임에 못 올린다** |
| 범위 | 얼굴만 변환, 배경·몸은 실사 유지 | 변환 영역과 실사 영역의 **경계가 드러난다** |
| 표정 유지 | 웃으면 웃고, 시선이 맞아야 함 | 얼굴을 안 바꾸면 신원이 안 지워진다. **정면 충돌** |
| 비식별화 | 원본 인물로 재식별되면 안 됨 | 위 항목과 트레이드오프 |
| 저작권 | 실제 영상 푸티지로 학습 불가 | 학습 데이터는 합성 이미지만 |

**마지막 두 줄이 이 프로젝트를 어렵게 만든 진짜 원인이다.** 영상에서 발생하는 문제를
영상 데이터 없이 풀어야 했다.

## 2. 기술 선택 — 왜 teacher-student 증류인가

### 검토한 대안

| 접근 | 기각 사유 |
|---|---|
| 기성 애니 스타일 모델 사용 | **라이선스.** `animegan2`의 코드는 MIT지만 가중치 출처가 불명확하고, 원본 `AnimeGANv2`는 비상업 전용이다. 파생 여부가 [공개 이슈에서 미해결](https://github.com/bryandlee/animegan2-pytorch/issues/25) |
| 확산 모델을 런타임에 직접 | **속도.** 장당 12.6초 = 요구 예산의 380배 |
| unpaired GAN (CycleGAN·AnimeGAN 계열) | 시도했고 실패했다. adversarial 과대 → 붕괴, gram 정규화 버그, 그리고 진짜 원인은 워밍업이 VGG-only라 평균색으로 무너진 것. 결과물은 유화가 됐다 |
| **paired 증류 (채택)** | 오프라인에서 확산 모델로 정답 쌍을 만들고, 작은 CNN이 그 매핑만 배우게 한다 |

증류를 고른 이유는 속도만이 아니다. **paired 학습이면 화풍을 프롬프트로 통제할 수 있고,
그 결과를 정량 비교할 수 있다.** unpaired GAN은 학습이 어디로 갈지 통제가 안 됐다.

### 구성

```
[오프라인] 실사 사진 → Qwen-Image-Edit-2511 + Anime LoRA (teacher, 20B) → 페어 코퍼스 13,500쌍
                                    ↓ 증류
[런타임]   영상 → YOLOX 검출(TensorRT) → occupancy 0.65 크롭
              → 학생 CNN 4.06M (ONNX + TensorRT, 512²)
              → Lab 색 정합 → 선 강조 → 타원 페더 합성 → NVENC
```

teacher는 **런타임에 실리지 않는다.** 데이터 생성 전용이다.

## 3. 데이터 설계

합성 인물 데이터셋(SFHQ-T2I)에서 13,500장을 선별했다. 그냥 자르지 않고 세 가지를 통제했다.

- **연령 분포** — 프롬프트에서 나이를 정규식으로 추출해 adult 80% / senior 10% / teen 5% / child 5%
- **고질감 프롬프트 상한** — "주름", "모공", "거친 피부" 등 13개 키워드를 버킷당 5%로 제한.
  teacher가 이런 입력에서 그래픽노블 쪽으로 이탈하는 경향이 있었다
- **비사진 프롬프트 제외** — 회화·일러스트·3D 렌더 요청 1,595장과, 데이터셋 저자가 품질을 경고한
  DALL-E 3 출처 1,123장 제외

### 피부톤 편향 검사

QC 중 **갈색 피부 여성이 금발 백인으로 바뀐 사례**를 발견해 전수 측정했다(ITA 기반).

출력 ITA가 입력 구간별로 단조증가해 **상대 순서는 보존**되지만, 범위가 111 → 42로 **62% 압축**되며
밝은 쪽으로 이동한다. 다만 ITA는 "어두운 피부"와 "어두운 조명"을 분리하지 못하고
해당 데이터셋에는 역광·저조도가 많아, **자동 판정을 그대로 신뢰하지 않고 육안 확인을 병행**했다.

이건 해결한 문제가 아니라 **측정해서 알고 있는 문제**다.

## 4. 6주간 결과물이 흐렸다 — 그리고 원인은 모델이 아니었다

가장 오래 붙잡은 문제다. 학습을 여러 번 돌려도 출력이 사진에 가깝고 물렀다.
학습률·용량·손실 가중치를 바꿔봐도 `l1`이 40,000스텝 내내 평평했다.

**원인은 셋이었고, 전부 모델 밖에 있었다.**

### ① 얼굴이 아니라 사진 전체를 학습하고 있었다 (가장 큰 원인)

전체 인물 사진을 512로 리사이즈해 넣고 있었다. 그러면 512² 안에서 얼굴이 차지하는 픽셀은 일부고,
모델 용량의 대부분이 배경·옷·머리에 쓰인다. 정작 화풍이 드러나야 할 눈·입·윤곽은
몇십 픽셀 수준으로 들어갔다.

학습 단위를 **얼굴 크롭**으로 바꾸자 val L1이 **0.1084 → 0.0526**으로 떨어졌다. 같은 날 3시간 만이었다.

> **교훈: 모델을 의심하기 전에 모델이 무엇을 보고 있는지 확인한다.**

### ② adversarial을 0으로 두고 있었다

L1 + perceptual만으로는 조건부 평균에 안착한다. 하나의 입력에 대응하는 그럴듯한 출력이 여러 개일 때
L1의 최적해는 그것들의 **평균**이고, 평균은 흐리다. 구조적으로 선명해질 수 없는 설정이었다.

`adv 0.15`를 넣자 바로 선명해졌고, 최종적으로 1.5까지 올렸다. LSGAN의 평형점은 D=0.25인데
전 구간 0.20~0.27로 안정적으로 유지됐다.

### ③ 구조가 "다시 그리기"가 아니라 "덧칠하기"에 맞춰져 있었다

기존 생성기에는 **입력 픽셀을 출력까지 그대로 나르는 경로**가 있었고, 병목이 얕아
얼굴 전체를 한눈에 보지 못했다. 구조를 다시 설계했다 → [다음 장](#5-아키텍처-재설계--덧칠하는-망에서-다시-그리는-망으로)

## 5. 아키텍처 재설계 — "덧칠하는 망"에서 "다시 그리는 망"으로

### 기존 구조와 그 설계 의도

출발점은 animegan2 계열의 인코더-디코더에 U-Net skip과 PixelShuffle 업샘플을 붙인 것이었다.

```
입력 512²
  in_conv  7×7          → /1, 32ch  ─────────── skip1 ─────────┐
  down1    stride 2     → /2, 64ch  ──── skip2 ────┐           │
  down2    stride 2     → /4, 128ch               │           │
  mid      InvertedResidual × 4  (병목 = /4)       │           │
  up1      PixelShuffle → /2, 64ch  ← concat ─────┘           │
  up2      PixelShuffle → /1, 32ch  ← concat ─────────────────┘
  out      1×1 + Tanh
```

**`/1` skip은 실수가 아니라 의도된 선택이었다.** 초기 실험에서 출력이 유화처럼 뭉개지는 문제가 있었고,
인코더 첫 층의 고해상도 선·경계를 디코더 마지막에 직결하면 그게 잡혔다. 실제로 효과가 있었다.

### 무엇이 문제였나

문제는 그 skip이 **너무 잘 작동했다**는 것이다.

`/1` skip은 인코더 첫 층 출력(원본 해상도, 입력의 선·질감이 거의 그대로 남아 있는 특징 맵)을
디코더 마지막 층에 **concat**한다. 디코더 입장에서 가장 쉬운 해법은
**그 채널을 거의 그대로 통과시키고 색만 바꾸는 것**이다.

그리고 학습이 정확히 그 방향으로 갔다. 결과물은 카툰이라기보다 **입력을 예쁘게 덧칠한 사진**이었다.
스타일라이저가 아니라 **리페인터**로 동작하고 있었다.

두 번째 문제는 **수용영역**이다. 병목이 `/4` 하나에 3×3 컨볼루션만 쓰므로,
512 입력에서 유효 수용영역이 100~150px 수준으로 추정됐다. 얼굴 크롭 512²에서
**눈·코·입의 상대 비율 같은 전역 구조를 한 번에 보지 못한다.** teacher는 눈을 키우고 코를 단순화하는데,
그런 변환은 얼굴 전체를 봐야 일관되게 적용할 수 있다.

### 먼저 검증한 것 — 구조가 원인이 맞는가

구조를 뜯기 전에 **"현재 구조가 애초에 그런 변형을 표현할 수 있는가"** 부터 확인했다.
32쌍만 놓고 과적합시켰다(일반화를 포기하고 표현력만 본다).

| 신원 cos | 화풍 L1 | 톤 L1 |
|---:|---:|---:|
| 0.600 | **0.0386** | **0.0215** |

학생은 teacher의 눈 크기·턱선·코 단순화·머리 형태를 거의 그대로 재현했다.
**"구조가 형태를 못 바꾼다"는 가설은 반증됐다.** 남은 차이는 잔주름·속눈썹 같은 고주파뿐이었다.

즉 문제는 **표현력의 부재가 아니라 편향**이었다. 구조가 복사를 너무 쉽게 만들어놨기 때문에,
일반화 상황에서 학습이 항상 복사 쪽 국소해로 빠졌다. 이 진단이 설계 방향을 정했다 —
**용량을 키우는 게 아니라 복사를 어렵게 만든다.**

### 새 구조 (`deep8`)

```
입력 512²
  in_conv  7×7          → /1,  32ch
  down1    stride 2     → /2,  64ch  ─── s2 ────────────┐
  down2    stride 2     → /4, 128ch  ── s4 ───┐         │
  down3    stride 2     → /8, 192ch           │         │
  mid      InvertedResidual × 6  (병목 = /8)   │         │
  up1      PixelShuffle → /4, 128ch  ← gate ──┘         │
  up2      PixelShuffle → /2,  64ch  ← gate ────────────┘
  up3      PixelShuffle → /1,  32ch    (skip 없음)
  out      1×1 + Tanh
```

바꾼 것은 셋이고, 각각 목적이 다르다.

**① `/1` skip 제거 — 복사 경로 차단**

원본 해상도 skip을 아예 없앴다. 마지막 업샘플 뒤에는 디코더 자신의 특징만 남는다.
**입력 픽셀을 그대로 나를 방법이 없으므로 얼굴 요소를 다시 그리는 것 외에 선택지가 없다.**

당연히 대가가 있다 — 초기 실험에서 이 skip을 넣었던 이유(유화화 방지)가 되살아날 수 있다.
그건 다음 항목으로 보완했다.

**② concat skip → 학습형 게이트 덧셈**

남은 `/2`·`/4` skip은 concat이 아니라 **덧셈**으로 바꾸고, 그 세기를 학습 파라미터로 뒀다.

```python
class GatedSkip(nn.Module):
    def __init__(self, init_gain=0.1):
        self.logit = nn.Parameter(logit(init_gain))      # sigmoid 로 0~1 보장
    def forward(self, decoded, skip):
        return decoded + torch.sigmoid(self.logit) * skip
```

초기값을 **0.1로 약하게** 준 것이 핵심이다. concat은 디코더가 언제든 skip 채널에 의존할 수 있게 하지만,
약하게 초기화된 덧셈 게이트는 **학습 초반에 디코더가 스스로 그리도록 강제**한다.
그러고도 고해상도 정보가 정말 필요하면 게이트가 열린다. **선택지를 없애는 게 아니라 기본값을 바꾼 것이다.**

**③ 병목을 `/4` → `/8`, residual 4 → 6 — 수용영역 확대**

한 단계 더 내려가면 같은 3×3 컨볼루션이 원본 기준 두 배 넓이를 본다.
얼굴 전체 비율을 한 번에 보고 일관된 양식화를 적용할 수 있다.
채널은 `ch×6`(192)으로 두어 다운샘플로 잃는 정보를 채널로 보상했다.

### 결과

| | 파라미터 | 512² 추론 | val L1 |
|---|---|---|---|
| 기존 (legacy, ch=48) | ~3M | ~75ms eager | 0.1084 (전체 사진 학습 기준) |
| **deep8 (ch=32)** | **4.06M** | ~33ms eager / TRT 실측 예산 내 | **0.0567** (얼굴 크롭 999장 probe) |

파라미터는 늘었지만 **연산은 오히려 줄었다.** 무거운 층이 `/8`로 내려가 해상도가 1/4이 됐기 때문이다.
**용량을 키우면서 속도를 벌었다** — 다운샘플 한 단계의 부수 효과였다.

그리고 이 구조가 이후 모든 개선의 토대가 됐다. `/1` skip이 남아 있었다면
edge loss로 선을 감독해도 디코더가 skip에서 선을 그대로 가져왔을 것이고,
equivariance loss로 일관성을 제약해도 입력 픽셀을 복사하는 한 입력의 지터가 그대로 전달됐을 것이다.

> **교훈: 모델이 원하는 답을 안 낼 때, 용량을 키우기 전에
> "지금 구조에서 가장 쉬운 해법이 무엇인가"를 먼저 본다.**
> 학습은 항상 가장 쉬운 길로 간다. 그 길을 막는 것이 더 싸다.

## 6. 판정 체계를 만든 것이 이 프로젝트의 절반이다

**이 프로젝트에서 가장 많이 실패한 것은 학습이 아니라 판정이다.**
잘못된 지표로 잘못된 결론을 낸 사례가 세 번, 지표와 육안이 갈린 것이 여섯 번이다.

### 사례 1 — 화풍을 고르는 지표에 "얼마나 변했는가"가 없었다

프롬프트 4조건을 비교해 정합(ECC)·일관성(CV)·PNG 크기로 최적안을 골랐다. 4개 항목 1위였다.

**그런데 ECC가 높다는 건 원본과 덜 변했다는 뜻이었다.** 채택된 조건이 이긴 이유는
가장 적게 바꿨기 때문인데, 그것을 "정합이 좋다"로 읽었다. 실제 프롬프트에는
`Keep the exact same pose, gaze and expression` 즉 **얼굴을 바꾸지 말라는 지시**가 들어 있었다.

이 하나가 이후 문제를 전부 설명했다 — teacher 신원 cos 0.799(100% 동일인),
학생이 화풍을 못 배움(배울 델타 자체가 작음), l1이 평평함(입력 ≈ 타겟), 결과가 "반 카툰화".

> **교훈: 변환 품질을 재는 지표군에 반드시 "변화량"을 넣는다.
> 정합·일관성만 보면 아무것도 안 하는 조건이 항상 이긴다.**

### 사례 2 — Laplacian 분산으로 디테일을 재다가 두 번 속았다

Laplacian 분산을 "디테일 밀도"로 썼다. 그런데 **굵은 윤곽선과 잔주름을 구분하지 못한다.**
애니 화풍은 전자를 늘리고 후자를 지우므로 두 변화가 상쇄되어 순위가 뒤집힌다.

한 번 데이고 문서에 "쓰지 마라"고 적어뒀는데도 **6주 뒤에 같은 실수를 반복**했다.
"디테일 천장에 부딪혔다, 상관 −0.801"이라는 결론을 냈고, 지표를 다시 만들어 재니
상관 **+0.340**, 학생/teacher 비 **0.97**이었다. 천장 가설 자체가 지표 아티팩트였다.

대체 지표를 직접 만들었다 — Canny 엣지 위치의 gradient 크기(edge_contrast),
비엣지 영역 국소 표준편차(flatness), edge_density, PNG 압축 크기.

### 사례 3 — 지표가 전부 좋아졌는데 영상은 나빠졌다

입력 충실도를 올리는 증강을 적용했다. 결과는 **이동 증폭 1.30 → 1.06, 코퍼스 지표 전 항목 개선**.
수치만 보면 명백한 성공이었다.

영상에서는 볼에 주근깨가 찍히고, 눈썹이 일렁이고, 눈이 무너졌다. **기각했다.**

원인을 추적해보니, 면적 평균 지표는 **작지만 대비가 큰 구조(눈)가 출렁이는 것을 볼 수 없다.**
눈은 화면의 2%도 안 되므로 전체 평균에 묻힌다. 이후 판정에는
**연속 프레임의 해당 영역만 잘라 붙인 스트립**을 함께 봤다.

> **교훈: 지표는 후보를 좁히는 용도, 판정은 육안.** 이 원칙을 어길 때마다 시간을 잃었다.

### 사례 4 — "흔들린다"를 숫자로 만들기

"선이 흔들린다"는 주관적 불만이었다. 이걸 측정 가능한 것으로 바꿔야 개선 여부를 판정할 수 있었다.

입력을 1픽셀 밀고, 출력이 얼마나 변하는지 쟀다. 그리고 **출력을 같은 양만큼 되돌린 뒤에도 남는 잔차**를
따로 분리했다. 이게 "순수한 평행이동으로 설명되지 않는 변화" — 즉 **비등변성**이다.

| 교란 | 출력 변화 배율 |
|---|---|
| **1px 이동** | **1.826** |
| 밝기 +2 | 0.625 |
| JPEG q90 | 1.655 |

**공간 이동만 증폭된다.** stride-2 convolution의 에일리어싱이 원인이고, 런타임 후처리로는 못 고치는
모델 성질이다. 이 숫자가 이후 모든 안정성 개선의 판정 기준이 됐다.

---

### 사례 5 — 육안도 그대로는 못 믿는다

지표가 여섯 번 틀렸으니 육안을 기준으로 삼았다. 그런데 **어느 쪽이 새 모델인지 알고 보면 판단이 기운다.**

그래서 업계 프로토콜(Emu, Diffusion-DPO)을 솔로 규모로 옮겼다.

- **고정 홀드아웃 200장** — 수염·안경·머리 가림·얼굴 크기·연령·피부톤으로 층화.
  희소 카테고리를 먼저 확보한다. 무작위로만 뽑으면 수염 얼굴이 몇 장 안 들어와 그 실패를 못 본다
- **좌우 무작위 + 라벨 은닉** — 다 보고 나서 정답 공개
- **질문 분리** — Q1 "그림으로서 나은가"는 **원본을 숨기고**, Q2 "원본을 살렸나"는 보여주고

첫 적용에서 **믿음 하나가 뒤집혔다.** 우리는 "안정성 손실의 대가로 선 굵기를 내줬다"고 판단하고
그걸 되돌리는 후처리를 만들었는데, 블라인드에서는 그 손실이 재현되지 않았다(52.9%, p=0.86).
원래 판단은 어느 쪽이 새 모델인지 알고, 특정 프레임 몇 장만 본 결과였다.

그리고 파이프라인 전체는 검증됐다 — **기준선 대비 85.2% 승, p < 0.0001** (아래 7장).

> **교훈: 지표를 못 믿어 육안으로 갔다면, 육안도 블라인드로 만들어야 한다.**
> 안 그러면 판정 기준을 바꾼 게 아니라 편향의 종류만 바꾼 것이다.

## 7. 성능 개선 — 단일 변수 파인튜닝과 가중치 산술

기준선을 확보한 뒤에는 **처음부터 다시 학습하지 않고 이어붙이는 방식**으로,
한 번에 하나씩만 바꿨다.

```
기준선 (30,000스텝)
   │  문제: 선이 흐리다
   │  진단: teacher를 직접 통과시켜 대조 → teacher는 선명하다. 학생이 자기 타겟보다 무르다
   │  발견: 선을 직접 감독하는 손실(w_edge)이 0이었다
   ▼
세대 2: w_edge 0 → 3.0                     val L1 0.1611 → 0.1448
   │  문제: 선이 굵어진 만큼 흔들림이 눈에 보인다
   │  진단: 측정해보니 흔들림은 오히려 줄었다(1.826 → 1.546).
   │        원래 있던 흔들림이 선이 굵어져 드러난 것
   ▼
세대 3: w_equiv 0 → 10                     비등변 1.103 → 0.569
   │  결과: 화풍 유지(val L1 0.1472)한 채 안정성만 확보
   │  대가: 선 굵기를 조금 내줌
   │  대응: 모델을 되돌리지 않고 런타임 후처리로 회수
   ▼
세대 4: 타겟 생성 순서 변경             선명도 A/B 67.9% 승, 그러나 신원 0.602 → 0.776
   │  판정: 품질은 이겼으나 **제품 게이트에서 탈락** (아래)
   ▼
세대 5: 가중치 선형 보간 (model soup)   0.75·세대3 + 0.25·세대4
      결과: 두 부모보다 나은 지점이 존재했다
```

### 진단이 개선보다 중요했던 지점

세대 2에서 "선이 흐리다"를 학생 문제로 놓고 학습만 반복하던 중, **teacher가 병목인지 학생이 병목인지
한 번도 확인하지 않았다**는 것을 깨달았다. 영상 프레임을 teacher에 직접 통과시켜 3열 대조 시트를 만들었다.

- teacher는 선명했다 → **천장은 teacher가 아니다**
- 학생/teacher 화풍 유사도 0.97 → **용량도 아니다**
- 남은 것은 학생이 자기 타겟보다 무르다는 것 → 손실 구성 문제

그리고 손실 인자를 확인해보니 `w_edge`가 0이었다. **코퍼스 규격을 바꾸는 과정에서
그전까지 켜져 있던 손실이 빠진 채 30,000스텝이 돌았고 아무도 눈치채지 못했다.**

> **교훈: 규격을 바꿀 때 손실 가중치를 이전 실행에서 복사해 오고,
> 첫 100스텝 로그에서 각 항이 이전과 같은 자릿수인지 대조한다.**

### 사람 평가로 검증 (2026-08-05)

위 세대별 수치는 전부 지표다. 블라인드 페어와이즈로 따로 검증했다.

| 비교 | Q1 그림으로서 | Q2 원본 충실도 |
|---|---|---|
| **기준선 vs 최종** (n=60) | **최종 85.2% 승, p < 0.0001** | 52/60 무승부 |
| 세대2 vs 세대3 (n=40) | 52.9%, p = 0.86 | 45.7%, p = 0.74 |

두 결과를 합치면 기여도가 분해된다 — **눈에 보이는 개선은 전부 세대 2(`w_edge`)가 만들었고,
세대 3(`w_equiv`)은 정지 화질을 깎지 않고 시간축 안정성만 가져왔다.**
Q2 가 52/60 무승부라는 것은 **화질을 올리면서 원본 충실도는 건드리지 않았다**는 뜻이다.

효과 크기 참고: Emu 가 SDXL 을 이긴 것이 68%, Diffusion-DPO 가 70%다.

### 시간적 안정성 — 영상 없이 영상 문제 풀기

저작권상 실제 영상으로 학습할 수 없다. 정지 이미지만으로 프레임 간 일관성을 배우게 해야 했다.

equivariance loss를 썼다 — 입력을 무작위로 warp한 것의 출력과, 출력을 같은 만큼 warp한 것을
일치시키는 제약이다. **"입력이 움직이면 출력도 같이 움직여야 한다"를 정지 이미지 한 장으로 가르친다.**

| | 이동(증폭) | **비등변** | 밝기 | JPEG |
|---|---|---|---|---|
| 적용 전 | 1.546 | **1.103** | 0.625 | 1.792 |
| 적용 후 | 1.415 | **0.569** | 0.808 | 1.293 |

비등변 48% 감소, val L1은 0.1448 → 0.1472로 유지. **화풍을 내주고 산 안정성이 아니다.**
JPEG 민감도까지 28% 떨어진 것은 예상하지 못한 부수 효과였다.

### 품질 지표가 이긴 모델을 기각한 판단

세대 4는 타겟을 다시 구운 실험이다. 기존 타겟은 *넓은 사진을 애니화한 뒤 얼굴을 잘라낸* 것이라,
타겟에 담긴 얼굴 디테일이 teacher 가 좁은 화면 안에 그린 만큼으로 제한돼 있었다.
순서를 뒤집어 **먼저 자르고 그 크롭에 teacher 를 다시 돌려** 3,000쌍을 만들었다(10.5시간).

의도대로 됐다. 수염과 머리 가닥이 살아났고, **블라인드 A/B 에서 67.9% 로 이겼다(p = 0.0127).**

그런데 같은 원인이 반대편에서도 작동했다.

| | 세대 3 | **세대 4** |
|---|---|---|
| 블라인드 A/B (그림으로서) | — | **67.9% 승, p = 0.0127** |
| **신원 잔존** (제품 목표 0.3) | 0.602 | **0.776** |
| teacher 타겟 자체의 신원 | 0.540 | 0.659 |

teacher 가 얼굴을 크게 보면 **원본 이목구비도 더 성실하게 따라 그린다.**
선이 선명해진 것과 신원이 남은 것은 같은 원인의 두 얼굴이었다.

이것은 비식별화 모듈이다. **원본 인물에 더 가까운 카툰은 아무리 예뻐도 제품 목적을 부정한다.**
그래서 A/B 에서 이긴 모델을 단독 교체 후보에서 기각했다.

중요한 것은 **이 게이트를 3,000장을 굽기 전에 미리 정해뒀다는 점**이다
(*"신원 증가폭이 크면 계획을 바꾼다"*). 사후에 정했다면 67.9% 라는 숫자 앞에서
합리화했을 가능성이 높다.

> **교훈: 품질 지표가 이긴 모델도 제품 지표가 지면 기각한다.
> 그 판정선은 실험을 시작하기 전에 적어둔다.**

### 기각한 모델을 버리지 않는 법 — 가중치 산술

세대 4는 원하는 것(선명도)과 원하지 않는 것(신원)을 함께 갖고 있었다.
그런데 세대 3과 세대 4는 **같은 손실 분지 안에 있다** — 한쪽에서 이어붙여 학습한 계보라
가중치 공간에서 멀지 않다. 그러면 재학습 없이 **가중치를 그냥 선형 보간할 수 있다**(model soup).

α = 0.25 / 0.50 / 0.75 세 지점을 만들어 측정했다.

| | 세대 3 (α=1.0) | **α = 0.75** | 세대 4 (α=0.0) |
|---|---|---|---|
| 신원 잔존 | 0.602 | **0.647** | 0.776 |
| 비등변성 | 0.569 | **0.473** | — |
| JPEG q90 민감도 | — | **1.162** | — |

두 가지가 나왔다.

1. **신원이 α 에 대해 완벽하게 선형이었다** — 0.25 스텝마다 정확히 +0.045.
   즉 *화풍 ↔ 신원* 교환비를 **재학습 없이 연속 다이얼로 조절할 수 있다.**
   제품 요구가 바뀌면 학습이 아니라 스칼라 하나로 대응한다.
2. **비등변성은 두 부모보다 좋았다**(0.569 → 0.473). 보간이 절충이 아니라 개선인 지점이 있었다.
   서로 다른 방향의 오차가 상쇄된 것으로 본다.

**기각된 세대 4는 삭제되지 않았다. 현재 프로덕션 모델의 25% 가 그것이다.**
비용 관점에서도 의미가 있다 — 10.5시간을 들여 구운 데이터가 "실패"로 폐기되지 않고 회수됐다.

> **교훈: 기각된 실험의 체크포인트를 지우지 않는다. 결과가 아니라 재료일 수 있다.**

### 손실 쪽 헤드룸이 끝난 것을 확인한 방법

수프 위에서 단일 변수 실험 두 개를 더 돌렸고 **둘 다 기각됐다.**

| 실험 | 바꾼 것 | 결과 |
|---|---|---|
| A | `w_edge` 3 → 5 | edge density 10.74 → 11.36% 인데 edge contrast 181.0 → **179.2** |
| B | `w_flat` 0 → 2.0 | flatness 0.95 → **1.03**, edge contrast 1.03 → 0.93 |

A 의 진단: Sobel L1 은 모든 gradient 를 동등하게 취급하는데 화소 수는 작은 gradient 쪽이
압도적으로 많다. 가중치를 올리면 **선이 굵어지는 게 아니라 잔선이 늘어난다.**
B 는 애초에 없는 문제였다 — 측정치가 이미 *타겟보다 평탄하다*고 알려주고 있었는데
그것을 읽지 않고 제안했다.

teacher 대비 학생의 화풍 지표를 보면 이유가 분명하다.

| 축 | 학생 / teacher |
|---|---|
| edge contrast (선 대비) | **1.03** — 이미 넘어섬 |
| flatness (면의 평탄함) | **0.95** — 이미 넘어섬 |
| edge density (선의 개수) | 0.85 — 유일하게 미달 |

**학생은 이미 자기 teacher 를 두 축에서 넘어섰다. 남은 천장은 학생이 아니라 타겟이다.**
따라서 다음 레버는 손실 가중치가 아니라 데이터 분포여야 한다는 결론에 도달했다.

## 8. 런타임 — 모델 밖에서 푼 문제들

모든 문제를 학습으로 풀 필요는 없다. 다음 세 가지는 런타임에서 해결하는 편이 훨씬 쌌다.

### 색이 떠 보이는 문제 — 네 세대

| 방식 | 결과 |
|---|---|
| 전역 평균/표준편차 전이 | 채도가 깎인다 |
| 저주파 색 전이 | **분홍 배경이 얼굴로 번졌다** |
| + 얼굴 타원 마스크 | 배경 오염은 막았지만 여전히 근사 |
| **Lab의 a·b를 입력에서 픽셀 단위로 복사** | **채택.** 색이 뜰 여지 자체가 없다 |

밝기는 스타일 결과에서, 색은 입력에서 가져온다. Lab 공간에서 두 축이 분리되므로 가능한 접근이다.

### 크롭 경계가 보이는 문제 — 원인이 색이 아니었다

색을 픽셀 단위로 맞췄는데도 경계가 보였다. 남은 축은 **밝기**뿐이었다.
애니 화풍은 평면 셀 셰이딩이라 저주파 밝기 분포가 실사와 다르다.

페더(feather)를 키우는 건 해법이 아니었다 — **단차를 흐릿한 띠로 바꿀 뿐**이다.
대신 밝기를 저주파/고주파로 분리해 **저주파만** 입력 것으로 교체했다.

```
L' = L + w · (lowpass(L_입력) − lowpass(L_출력))
```

고주파(그려진 선과 음영 대비)는 건드리지 않으므로 **선명도 손실 없이** 경계만 사라진다.

### 선명도 — 실패한 방법과 성공한 방법의 차이는 한 글자였다

unsharp mask는 실패했다. **양방향 오버슈트**라 경계 양쪽에 밝은 halo와 어두운 halo를 동시에 만들고,
그 halo가 프레임마다 흔들린다. 선명해진 게 아니라 **깜빡임을 새로 만든 것**이었다.

조사 끝에 Anime4K(MIT)의 line darkening을 찾았다. 차이는 한 글자다.

```
D = min(luma − blur(luma), 0)      ← 단측 클램프. 어두워지기만 한다
```

밝아지는 픽셀이 0개이므로 밝은 halo가 **구조적으로** 생기지 않는다.

영상 측정(모션 보정 프레임간 잔차 / 엣지 대비):

| 설정 | 흔들림↓ | 선명도↑ |
|---|---|---|
| 기준선 | 5.757 | 174.8 |
| 세대 2 (w_edge) | 4.868 | 176.3 |
| 세대 3 (w_equiv) | 3.299 | 167.5 |
| **세대 3 + darken** | **3.848** | **181.0** |

**세대 3 + 후처리가 두 축 모두에서 세대 2를 이긴다.** 여기서 순서의 원칙이 나왔다.

> **흔들림은 모델 성질이라 후처리로 못 고치고, 선 굵기는 후처리로 얹을 수 있다.
> → 안정성을 학습으로 먼저, 선명도를 후처리로 나중에.**

### 속도 — 5.55× → 1.02× 실시간

기능을 붙이다가 CPU 합성이 7.8ms → **167.1ms**로 퇴행했다.
원인은 큰 sigma(≈53) 가우시안 블러를 프레임당 두 번 호출한 것이었다(534px 크롭에 약 80ms/회).

저주파만 필요했으므로 **축소 → 작은 블러 → 확대**로 바꿔 1ms 미만으로 떨어뜨렸다.
같은 방식을 bilateral에도 적용해 16.1ms, **1.02× 실시간**으로 복귀했다.

## 9. 남은 과제 — 비식별화

**제품의 존재 이유인데 가장 오래 방치돼 있다.** 신원 cos 0.595, 목표 0.3이다.

그리고 이건 단순히 "아직 안 했다"가 아니라 **구조적 충돌**이다.

- **구조 보존형 스타일 모델은 원리적으로 신원을 못 지운다.** 강도를 두 배로 올려도 cos가
  0.086밖에 안 떨어진다(0.825 → 0.739). 채택한 LoRA의 셀링포인트가 "preserves pose, proportions"이고,
  **얼굴 인식이 보는 것이 바로 그 구조**다
- **화질 개선이 전부 이 축을 밀어 올린다.** 프레이밍을 넓히면 화질은 좋아지지만 cos가 0.823까지 오른다.
  타겟을 더 충실하게 만들어도 같은 방향이다
- 남은 수단은 학습 중 신원 임베딩을 밀어내는 손실(`id-loss`)인데, 화풍 손실과 정면으로 싸운다

**이 트레이드오프를 인지하고 있으면서도 화질을 먼저 개선한 것은 판단이었다.**
화풍이 불안정한 상태에서 id-loss를 켜면 두 개가 동시에 움직여 원인 분리가 불가능해진다.
화풍·안정성이 확정된 지금이 그것을 시작할 시점이다.

기타 미해결: 헤어라인 경계(머리 포함 세그멘테이션 필요), 작은 얼굴(현재 150px 미만은 모자이크로 처리),
속도의 목표 GPU 재측정.

## 10. 일하는 방식으로 남은 것

기술적 결론보다 오래 쓸 것들이다.

1. **원인을 확인하기 전에 학습부터 돌리지 않는다.** teacher가 병목인지 학생이 병목인지
   확인하는 데 하루가 걸렸지만, 그 전 6주 중 상당 부분은 확인 없이 돌린 시간이었다.
2. **지표는 후보를 좁히는 용도, 판정은 육안.** 지표와 사람 눈이 갈린 여섯 번 모두 눈이 맞았다.
   대신 "눈이 맞다"에 안주하지 않고 **왜 지표가 못 봤는지**를 매번 찾았다.
3. **그리고 육안도 블라인드로 만든다.** 지표를 못 믿어 눈으로 갔다면, 눈에도 같은 규율을 적용해야 한다.
   고정 홀드아웃 + 좌우 무작위 + 라벨 은닉 + 질문 분리. 도입 첫날 믿음 하나가 뒤집혔다.
4. **단일 변수.** 같은 방향으로 미는 변경이라도 결과가 나오면 하나씩 떼어낸다.
   한 번은 서로 다른 두 변수를 동시에 넣었다가 되돌렸다.
5. **기각 사유를 남긴다.** 안 되는 것을 두 번 시도하지 않기 위해 별도 색인 문서를 만들었다.
   실제로 같은 실수(Laplacian)를 반복했기 때문에 만든 것이다.
6. **실패를 지우지 않는다.** 각 세대의 가중치를 전부 보존한다.
   대조군이 없으면 "무엇이 효과였는가"를 다시 증명할 수 없다.
7. **라이선스를 먼저 확인한다.** 성능이 좋아 보이는 후보의 절반 이상이 비상업 라이선스로 탈락했다.
   나중에 발견하면 그때까지의 작업이 전부 무효가 된다.
